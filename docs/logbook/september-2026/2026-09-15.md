## Hal yang Dipelajari

### 1. Cara Kerja `tr100001.c` dan Linux Shared Memory

Pemrosesan data antrean Order Book (10 tingkat *bid/offer*) di sisi server ditangani langsung oleh kode C pada `tr100001.c`. Program ini tidak melakukan kueri SQL relasional atau pembacaan berkas fisik untuk mengambil antrean pasar, melainkan membaca langsung dari **Linux Shared Memory** (*Shared Memory IPC*).

Alur kerja `tr100001.c` berjalan sebagai berikut:

1. **Penerimaan & Parsing Masukan:** Menerima paket *stream* soket TCP dari klien, kemudian memisahkan kolom masukan (kode saham dan kode papan perdagangan) menggunakan fungsi `SepFieldLoad`.
2. **Pembentukan Kunci Komposit:** Menggabungkan kode saham dan papan pasar (misalnya `BBCA    RG  `) menggunakan fungsi `Set_Combind_Code`.
3. **Pencarian Indeks di Memori:** Melakukan pencarian biner (*binary search*) melalui `Stk_Jpbid_Shm_Bsearch` untuk menemukan indeks posisi antrean saham pada segmen memori bersama.
4. **Pembacaan Data Antrean dari Shared Memory:** Melalui *macro pointer* `STKJP(bidpt)`, program mengakses struktur data memori bersama (`STOCK_JPBID_SHM`) yang telah ditautkan ke RAM sistem operasi via `shmat()`. Program melakukan perulangan pada antrean beli (`valid_bid_cnt`) dan penawaran jual (`valid_offer_cnt`) untuk mengambil hingga 10 level harga dan volume:

```c
// tr100001.c: Pembacaan data antrean dari Linux Shared Memory
Set_Combind_Code(acComCode, SepFld[1].text, SepFld[2].text);

bidpt = Stk_Jpbid_Shm_Bsearch(acComCode);
if (bidpt < 0) {
    LOGGER("100001> Stk_Jpbid_Shm_Bsearch() Failed!!! [%s]\n", acComCode);
    return -1;
}

// Membaca antrean Bid (Beli)
for (i = 0, iCnt = 0; i < STKJP(bidpt).valid_bid_cnt; i++) {
    sprintf(tmp, "%ld|%ld|", STKJP(bidpt).jpbid[i].bid_prc,
            STKJP(bidpt).jpbid[i].bid_vol);
    strcat(OutImsi, tmp);
    tot_bid += STKJP(bidpt).jpbid[i].bid_vol;
    iCnt++;
    if (iCnt >= 10) break;
}

// Membaca antrean Offer (Jual)
for (i = 0, iCnt = 0; i < STKJP(bidpt).valid_offer_cnt; i++) {
    sprintf(tmp, "%ld|%ld|", STKJP(bidpt).jpbid[i].offer_prc,
            STKJP(bidpt).jpbid[i].offer_vol);
    strcat(OutImsi, tmp);
    tot_offer += STKJP(bidpt).jpbid[i].offer_vol;
    iCnt++;
    if (iCnt >= 10) break;
}
```

5. **Serialisasi Output:** Menggabungkan data tingkat harga dan volume ke dalam format string *pipe-delimited* (`|`) dan mengirimkan paket respons kembali ke klien melalui soket.

### 2. Mekanisme Kompilasi GCC dan Penggunaan Header pada C

Dalam pengembangan dan pemeliharaan modul backend berbasis C pada server Linux, proses kompilasi menggunakan GCC (*GNU Compiler Collection*) melibatkan dua tahapan utama:

1. **Tahap Kompilasi (Compilation):** Mengubah berkas kode sumber (`.c`) menjadi berkas objek biner (`.o`).
2. **Tahap Penautan (Linking):** Menggabungkan berkas objek dengan pustaka yang dibutuhkan menjadi berkas biner pustaka bersama (*shared library* `.so`) atau *executable*.

Parameter utama yang digunakan pada GCC meliputi:

- `-I<path>` (*Include path*): Menentukan direktori tempat *compiler* mencari berkas *header* (`.h`) yang disertakan melalui `#include`.
- `-L<path>` (*Library path*): Menentukan direktori tempat *linker* mencari berkas pustaka biner (`.so` atau `.a`).
- `-l<name>` (*Library name*): Menentukan pustaka spesifik yang akan ditautkan (misalnya `-lfuncmisc` menautkan berkas `libfuncmisc.so`).

#### Peran Berkas Header (`.h`)

Bahasa C tidak memiliki sistem modul modern seperti pada Python atau Dart. Berkas *header* (`.h`) digunakan sebagai deklarasi (*blueprint*) tanda tangan fungsi, struktur data (*struct*), dan definisi konstanta:

- Berkas implementasi seperti `funcmisc.c` memuat kode logika fungsi (misalnya implementasi `Set_Combind_Code` dan `Stk_Jpbid_Shm_Bsearch`).
- Berkas *header* seperti `convdata.h` atau `tip_shm.h` mendeklarasikan prototipe fungsi tersebut.
- Berkas `tr100001.c` cukup menyertakan berkas *header* terkait di baris awal untuk memanggil fungsi-fungsi eksternal tersebut secara valid tanpa perlu mendefinisikan ulang kode implementasinya.

### 3. Alur Pemanggilan Order Book pada Flutter Klien

Pada aplikasi mobile Flutter, saat ini belum terdapat mekanisme *streaming* untuk data Order Book. Klien hanya meminta data satu kali (*one-time request*) ketika pengguna membuka halaman yang menampilkan antrean saham.

Alur pemanggilan data pada klien melibatkan berkas berikut:

- **`lib/cubit/order_book_cubit/order_book_cubit.dart`:**  
  Mengelola *state* tampilan Order Book. Ketika halaman dibuka, fungsi `getOrderbook` dieksekusi:
  - Mendaftarkan fungsi penangan (*handler*) untuk TR `100001` ke `SocketService2`.
  - Mengirimkan permintaan data ke server secara asinkron (*fire and forget*).
  - Menerima respons array data antrean bursa melalui fungsi `setOrderbook`, lalu memperbarui *state* UI.

```dart
// lib/cubit/order_book_cubit/order_book_cubit.dart
getOrderbook({required String code}) async {
  emit(getOrderBookInitial());

  // Mendaftarkan callback untuk menangani respons
  SocketService2().registerHandler("100001", (response) {
    setOrderbook(response: response);
  });

  // Pengiriman TR ke server
  SocketService2().sendToTr(
    trNo: '100001',
    data: {
      "code": code,
      "board": 'RG',
    },
  );
}
```

- **`lib/utils/socket2.dart`:**  
  Menyediakan layanan koneksi soket TCP langsung ke server bursa. Metode `sendToTr` mengemas parameter permintaan (`code` dan `board: 'RG'`) ke dalam paket protokol biner TCP dan mengirimkannya ke port server gateway. Respons yang diterima selanjutnya diarahkan kembali ke *handler* yang telah didaftarkan pada Cubit.
