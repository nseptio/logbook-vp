## Hal yang Dipelajari

### 1. Anatomi Komponen pada Trade Flow Chart

Grafik Trade Flow menyajikan dinamika pertarungan pembeli dan penjual agresif sepanjang jam perdagangan bursa dalam satu tampilan visual terpadu:

![Trade Flow Chart View](/images/september-2026/2026-09-08/01.jpg)

Komponen utama yang menyusun grafik ini antara lain:

- **Dual-Axis (Dua Skala Nilai):**
  - **Sumbu Y Kanan (Harga Saham):** Menampilkan skala harga saham (misal: 180 s/d 194 pada contoh saham BUMI). Garis biru merefleksikan pergerakan harga (*price action*) sepanjang hari.
  - **Sumbu Y Kiri (Aliran Dana / Net Value/Volume):** Menampilkan nilai transaksi bersih dalam satuan Rupiah (Billion) atau Lot (Kuantitas), dari nilai minus (distribusi) hingga positif (akumulasi).
  - **Sumbu X (Waktu Perdagangan):** Menunjukkan linimasa sesi bursa mulai pukul 09:00 hingga penutupan (16:00).
- **Batang Volume Net Flow:**
  - **Batang Hijau (ke atas):** Mengindikasikan **Net Buy** pada menit tersebut, di mana nilai pembelian agresif (HAKA) lebih dominan dibandingkan penjualan agresif.
  - **Batang Merah (ke bawah):** Mengindikasikan **Net Sell** pada menit tersebut, di mana aksi jual langsung ke antrean bid (HAKI) mendominasi pasar.
- **Indikator Sentimen (*Net Dist / Net Acc Gauge*):**
  - Berupa *bar gauge* gradien merah ke hijau dengan jarum penunjuk yang merangkum total sentimen pasar harian apakah saham tersebut sedang mengalami akumulasi bersih (*Net Acc*) atau distribusi bersih (*Net Dist*).

### 2. Mekanisme dan Algoritma "Big Money"

Pada antarmuka grafik, pengguna dapat beralih antara filter **All Trades** dan **Big Money**:

- **Mengapa Diperlukan Filter Big Money?**  
  Pada grafik reguler (*All Trades*), pergerakan sering kali dipenuhi oleh transaksi ritel bernilai kecil (*noise*). Filter *Big Money* berfungsi untuk menyaring transaksi ritel tersebut sehingga pengguna dapat fokus melihat jejak transaksi pemodal besar (*smart money* atau institusi) yang memiliki pengaruh riil terhadap arah tren harga.

- **Algoritma Ambang Batas Persentil (P90):**  
  Penentuan transaksi yang tergolong *Big Money* menggunakan algoritma klasifikasi berbasis statistik:
  1. Sistem mengumpulkan data rata-rata lot per order (`buyLotPerOrder` dan `sellLotPerOrder`) dari riwayat perdagangan 7 hari terakhir.
  2. Data tersebut diurutkan secara *ascending*.
  3. Sistem menetapkan ambang batas (*threshold*) pada **persentil ke-90 (P90)** atau 10% transaksi teratas.
  4. Setiap menit transaksi intraday kemudian dievaluasi: jika rata-rata order pada menit tersebut melampaui ambang batas P90, maka volume pada menit tersebut dihitung sebagai aliran dana *Big Money*.

- **Derived Data (Data Turunan):**  
  Data *Big Money* dihitung langsung (*purely derived*) dari dataset *All Trades* di sisi aplikasi. Pendekatan ini memastikan data selalu konsisten tanpa memerlukan panggilan jaringan atau *endpoint* terpisah.

### 3. Data yang Dibutuhkan untuk Membentuk Chart

Untuk merender grafik Trade Flow secara lengkap, sistem membutuhkan alur data dua arah melalui protokol TR:

#### A. Data Input (Parameter Permintaan dari Klien)
Aplikasi mengirimkan parameter kriteria saham dan rentang waktu yang diinginkan:

| Parameter | Tipe | Contoh | Deskripsi |
| :--- | :--- | :--- | :--- |
| `stockcode` | String | `"BUMI"` | Kode saham yang dianalisis. |
| `boardcode` | String | `"RG"` | Papan perdagangan (`RG` = Pasar Reguler). |
| `date_from` | String | `"20260826"` | Tanggal awal data (format `YYYYMMDD`). |
| `date_to` | String | `"20260826"` | Tanggal akhir data (intraday menggunakan tanggal yang sama). |
| `data_type` | String | `"val"` / `"vol"` | Satuan nilai yang ditampilkan (`val` untuk Rupiah, `vol` untuk Lot). |

#### B. Data Output (Hasil Olahan Server)
Server mengembalikan data dalam dua bentuk:
1. **Deret Waktu Menit (Array Rekaman Intraday):**
   - `time`: Penanda waktu (misal: `"09:01"`) untuk memetakan koordinat sumbu X.
   - `price`: Titik harga penutupan menit bersangkutan untuk membentuk garis harga (*Line Chart*).
   - `net_buy`: Nilai pembelian agresif bersih untuk tinggi batang hijau.
   - `net_sell`: Nilai penjualan agresif bersih untuk tinggi batang merah.
2. **Data Agregasi Harian:**
   - Total frekuensi dan akumulasi nilai beli vs jual untuk menentukan posisi jarum pada *gauge indicator*.

### 4. Tiga Perspektif Penyajian Data

Selain grafik (*Chart View*), Trade Flow juga menyajikan data melalui dua tampilan pelengkap:

#### A. Price View (Breakdown Fraksi Harga)

![Trade Flow Price View](/images/september-2026/2026-09-08/02.jpg)

- Mengelompokkan transaksi berdasarkan tiap tingkat [[fraksi-harga|fraksi harga]] (*group by price*).
- Menampilkan frekuensi jual (`S.Freq`), nilai jual (`S.Val`), tingkat harga (`Price`), serta nilai beli (`B.Val`).
- Berguna untuk mengidentifikasi pada tingkat harga berapa terjadi akumulasi terkuat atau aksi distribusi terbesar (*support/resistance volume*).

#### B. Time View (Log Kronologis Waktu)

![Trade Flow Time View](/images/september-2026/2026-09-08/03.jpg)

- Menampilkan riwayat transaksi per interval waktu berkala (misalnya interval 10 menit).
- Setiap baris waktu memuat nilai transaksi jual (`Sell Val`), rasio persentase tekanan (`%Sell` vs `%Buy`), serta visualisasi *mini chart bar* sentimen.
- Memudahkan pelacakan jam-jam krusial di mana momentum pasar berbalik (*momentum shift*).

### 5. Mempelajari Sistem File Linux

Selain Trade Flow, hari ini saya juga mempelajari struktur hirarki sistem file pada Linux (*Filesystem Hierarchy Standard*).

#### Filosofi *"Everything is a File"*
Di Linux, hampir semua hal diperlakukan dan direpresentasikan sebagai file—mulai dari file teks biasa, direktori, proses yang berjalan, koneksi socket, hingga perangkat keras (*hardware* seperti storage dan terminal). Seluruh komponen ini berada di bawah satu struktur pohon direktori tunggal yang bermula dari akar (`/` atau *root*).

Beberapa direktori utama yang telah dipelajari:

- **`/bin` (Essential Binaries):**  
  Berisi file executable program atau perintah dasar yang dapat digunakan oleh seluruh user sistem (misalnya: `ls`, `cp`, `cat`, `mkdir`, `bash`).
- **`/dev` (Device Files):**  
  Representasi hardware sebagai file khusus. Sistem dan aplikasi berkomunikasi dengan perangkat fisik maupun virtual melalui file di direktori ini (misalnya: hard disk `/dev/sda`, terminal `/dev/tty`, serta pseudo-device seperti `/dev/null` dan `/dev/urandom`).
- **`/etc` (System Configuration):**  
  Menyimpan file konfigurasi sistem dan aplikasi dalam format teks yang dapat diedit (misalnya: `/etc/hosts`, konfigurasi SSH `/etc/ssh/`, atau setting network).
- **`/mnt` (Mount Points):**  
  Tempat standar untuk me-*mount* filesystem atau storage eksternal secara sementara oleh administrator sistem (misalnya network share atau drive tambahan).
- **`/opt` (Optional Software):**  
  Direktori untuk instalasi aplikasi pihak ketiga (*third-party*) mandiri yang tidak berasal dari package manager resmi bawaan sistem operasi.
- **`/root` (Root User Home):**  
  Direktori *home* khusus untuk superuser (`root`). Terpisah dari `/home` agar superuser tetap dapat mengakses sistem meskipun partisi user mengalami gangguan saat *recovery*.
- **`/tmp` (Temporary Files):**  
  Menampung file-file sementara yang dibuat oleh sistem maupun aplikasi saat sedang berjalan. Pada umumnya isi direktori ini dibersihkan otomatis saat komputer di-*reboot*.
- **`/home` (User Home Directories):**  
  Direktori kerja personal bagi masing-masing user biasa (misalnya: `/home/username/`), yang memuat dokumen, file kerja, konfigurasi lokal (`~/.bashrc`), dan file SSH (`~/.ssh/`).

*(Catatan: Pembahasan ini baru mencakup sebagian struktur utama direktori sistem Linux dan akan terus dieksplorasi lebih mendalam).*
