# 4 September 2026

Berikut update kegiatan saya hari ini, 4 September 2026.

## Hal yang Dikerjakan

Melakukan proses *troubleshooting* pada aplikasi Flutter MyBesti.

### Bug
Ketika user logout dan kembali login dengan akun yang berbeda menggunakan `login_id` dan password, data yang tertampil adalah data akun sebelumnya, bukan akun yang baru saja login.

Contoh kasus yang dilakukan adalah login terlebih dahulu menggunakan akun pertama (`user_a`), lalu logout dan login kembali dengan akun kedua (`user_b`, password default `******`).

### Proses Troubleshooting

1. **Pengecekan Database:** Memeriksa database `kyc.dbo.signup_requests` apakah ada *identifier* yang sama, contohnya `id`, `NIK`, atau `login_id`. Hasilnya tidak ada identifier yang sama.
2. **Pengecekan Log TR dan Qtip di Server:** Dari kode project Flutter, nomor TR untuk login menggunakan `login_id` adalah **000102** dan nomor TR untuk mengambil data user adalah **300002**.  

   ```log
   # [Kiri] Log tr300002.py.log (Fetch Profile)
   (tr300002.py)out=1|33030XXXXXXXXXXX|[USER_A]|[REDACTED_ADDRESS]|...

   # [Kanan] Log Qtip001 (Proses Login)
   16:06:09.736> 000102> DATA
   1|1|Success Login|viewer|[USER_B]|SALES21|RMPXXXX|...
   16:06:09.736> 000102> TR000102_ RETURN![193]
   ```
   *\*) Kiri adalah log dari `tr300002.py.log`, kanan merupakan log `Qtip001`.*  
   Berdasarkan log Qtip001, login berhasil dengan akun kedua (`user_b`), namun ketika mengambil data akun dengan tr300002, data yang terambil justru data akun sebelumnya (`user_a`).
3. **Analisis Script TR:** Pada `tr300002.py`, pengambilan data user menggunakan filter `WHERE` dengan NIK, sedangkan hasil response dari `tr000102` tidak terdapat NIK. Ini menandakan bahwa aplikasi masih menggunakan data user sebelumnya untuk mengambil data karena jika user login menggunakan `login_id`, tidak ada data NIK user login.
4. **Analisis Widget Flutter:** Pada widget Flutter untuk logout, tidak ditemukan kode untuk membersihkan data user yang telah logout. Ini menandakan bahwa data user sebelumnya masih ada di *state* aplikasi dan terus digunakan untuk user yang baru saja login. Selain itu, hal ini menandakan bahwa data NIK tidak tertimpa jika login dengan `login_id`.  
   ![State Logout](/images/september-2026/2026-09-04/02.png)  
   *Logout hanya menghapus state `loginPIN`.*

### Solusi
- Pada file `lib/cubit/auth_cubit/auth_cubit.dart`, selain `loginPIN`, state user lain juga perlu dihilangkan, terutama NIK.
- Karena login menggunakan `login_id` tidak me-return NIK, kita perlu mengambil data NIK berdasarkan `login_id`.
- Pada file `lib/pages/navigator_page.dart`, perlu ditambahkan field untuk menampung `login_id`, lalu memanggil function `loadByLoginId` dari `lib/cubit/kyc_data_cubit/kyc_data_cubit.dart`.

## Hal Baru yang Dipelajari

### Mengenal dan Mengeksplorasi VitePress
Mempelajari VitePress sebagai *static site generator* berbasis Vite yang menggunakan Markdown sebagai sumber utama konten. Halaman web dapat mudah dibuat dari file `.md` tanpa perlu menggunakan HTML atau framework frontend dari awal.

### Memahami Use Case VitePress
Umumnya sesuai untuk website yang sebagian besar berisi konten terstruktur dan dokumentasi, seperti:
- Dokumentasi teknis dan API
- Tutorial dan panduan penggunaan
- *Blogging* atau *journaling*

### Ide Mempelajari VitePress karena Adanya Laporan Harian
- Laporan sebelumnya dikirim melalui email sehingga cukup sulit untuk menelusuri kembali laporan yang sudah lama.
- Dengan VitePress, setiap laporan dapat disimpan sebagai file Markdown dan dipublikasikan sebagai halaman web yang memiliki *navigation, sidebar, dan struktur halaman* yang lebih mudah ditelusuri.
- Markdown juga membuat penulisan laporan lebih sederhana karena tidak perlu berurusan langsung dengan HTML. Konten dapat ditulis sebagai teks biasa, sedangkan VitePress menangani proses mengubahnya menjadi halaman web.
- Karena hasil akhirnya merupakan *static site*, website ini relatif sederhana untuk di-*deploy* dan tidak membutuhkan backend khusus hanya untuk menyajikan isi laporan.
