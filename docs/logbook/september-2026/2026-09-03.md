### Mempelajari OpenSSH Config File

Salah satu keunggulan menggunakan aplikasi PuTTY adalah kita dengan mudah menyimpan konfigurasi sesi, sehingga dapat akses server dengan sekali klik. Tidak seperti ketika menggunakan OpenSSH, kita perlu untuk menulis command beserta parameternya `ssh -p [PORT] -i [PATH_TO_PRIVATE_KEY] [USERNAME]@[REMOTE_HOST]`.

Untuk dapat menyimpan konfigurasi sesi seperti PuTTY, kita perlu membuat config file. SSH config untuk menyimpan dan mengatur konfigurasi koneksi SSH, sehingga koneksi ke server dapat dilakukan dengan command yang lebih sederhana tanpa perlu menuliskan seluruh parameter setiap kali.

- Mempelajari bahwa OpenSSH menyediakan file konfigurasi pada `~/.ssh/config` yang dapat digunakan untuk membuat *profil koneksi SSH* dengan nama yang lebih mudah diingat. File config sebenarnya hanya sebuah text file biasa.
- Setiap profil dapat diberikan nama menggunakan `Host`, kemudian dikonfigurasi dengan beberapa parameter pada file `~/.ssh/config`:  
  ```ssh-config
  Host dev-server
      HostName dev.example.com
      Port 2222
      User devuser
      IdentityFile ~/.ssh/id_rsa
      LocalForward 5432 127.0.0.1:5432
  ```
- Dengan konfigurasi tersebut, koneksi yang sebelumnya memerlukan command panjang dapat dilakukan cukup dengan:  
  ```bash
  $ ssh dev-server
  Last login: Thu Sep  3 14:57:02 2026 from 192.168.1.50
  [devuser@dev-server ~]$ whoami
  devuser
  ```
  Sebagai catatan `IdentityFile` adalah lokasi di mana private key OpenSSH disimpan.
- File tersebut juga dapat digunakan pada *port forwarding* seperti `LocalForward`, sehingga file yang sama tidak hanya berfungsi untuk menyimpan credential dan alamat server, tetapi juga untuk mengatur perilaku koneksi SSH. Selain itu, konfigurasi ini juga dapat digunakan oleh berbagai tools yang menggunakan OpenSSH, termasuk *VS Code Remote - SSH*.

### Melanjutkan Eksplorasi Herdr

Pada [Herdr](https://herdr.dev/) terdapat fitur *Copy Mode* untuk mencari serta menyalin output command terminal.

- *Copy Mode* dapat digunakan untuk menelusuri output yang dihasilkan command yang telah dijalankan sebelumnya. Copy Mode dapat diakses menggunakan `prefix + [` pada konfigurasi default Herdr.
- Terdapat fitur pencarian di dalam Copy Mode menggunakan `/`, kemudian menggunakan `n` dan `N` untuk berpindah ke hasil pencarian berikutnya atau sebelumnya.
- Ketika masuk dalam Copy Mode, navigasi akan menggunakan VIM bindings.
- Fitur ini cukup berguna ketika bekerja dengan *output terminal yang panjang*, misalnya saat menjalankan atau membaca log. Daripada melakukan scroll manual untuk mencari keyword tertentu.
- Selain pencarian, Copy Mode juga memungkinkan bagian tertentu dari output dipilih dan disalin, sehingga informasi dari terminal yang panjang dapat diambil tanpa perlu menjalankan command kembali.

### CI/CD Pipeline pada Bitbucket

CI/CD (*Continuous Integration / Continuous Delivery atau Deployment*) merupakan praktik untuk mengotomatisasi proses dalam software development, mulai dari pengecekan dan pengujian perubahan kode hingga proses build dan deployment. Tujuannya adalah agar perubahan kode dapat divalidasi dan dirilis secara lebih konsisten dengan lebih sedikit proses manual.

Pipeline dapat diartikan sebagai rangkaian proses otomatis yang dijalankan oleh sistem CI/CD berdasarkan kondisi tertentu, misalnya ketika terdapat push pada branch tertentu. Bitbucket Pipelines mendefinisikan proses tersebut melalui file `bitbucket-pipelines.yml`.

Pada contoh ini, saya membuat pipeline untuk project Go sederhana yang terdiri dari beberapa tahap:
- **Test:** menggunakan `go test -v ./...` untuk menjalankan unit test.
- **Lint:** menggunakan `golangci-lint` untuk melakukan static analysis dan memeriksa potensi masalah pada source code.
- Jika di-push ke main branch, akan dibuat Docker image dan akan disimpan di Docker Hub registry.

Selain itu, mempelajari bagaimana Docker image dapat dibangun langsung dari pipeline menggunakan Docker service, kemudian di-*push* ke Docker Hub. Bitbucket Pipelines mendukung penggunaan Docker commands dalam sebuah step dengan menambahkan Docker sebagai service.

![Bitbucket Pipelines Docker Step](/images/september-2026/2026-09-03/04.png)

Untuk lebih detail, hasil pipeline dapat dilihat langsung pada dashboard Bitbucket Pipelines.
