# 12 September 2026

Berikut update kegiatan saya hari ini, 12 September 2026.

Fokus pekerjaan hari ini adalah mengimplementasikan dialog restorasi *draft* pada alur registrasi akun (*Opening Account / KYC*), serta melakukan *troubleshooting* dan penanganan kendala respons TR saat registrasi menggunakan NIK baru.

---

## 1. Implementasi Dialog Restorasi Draft KYC

Formulir pembukaan rekening (*Opening Account*) terdiri dari beberapa tahapan pengisian data. Untuk meningkatkan kenyamanan pengguna (*user experience*), dibuat fitur agar data yang telah diisi sebagian tidak hilang ketika pengguna menutup aplikasi di tengah proses.

Saat pengguna membuka kembali aplikasi dan mencoba mendaftar kembali dengan nomor yang sama, aplikasi akan mendeteksi keberadaan *draft* lokal dan menampilkan dialog konfirmasi:

![Dialog Konfirmasi Draft KYC](/images/september-2026/2026-09-12/02.png)

### Rincian Implementasi:
- **Pengecekan Draft Lokal:** Menggunakan layanan `KycDraftService` untuk mendeteksi apakah terdapat data pengisian KYC yang tersimpan di *local storage*.
- **Integrasi pada Alur OTP:** Dialog konfirmasi ditampilkan pada halaman OTP (`otp.dart`) setelah proses verifikasi nomor telepon berhasil.
- **Pilihan Tindakan Pengguna:**
  - **Lanjutkan:** Memuat kembali data *draft* yang tersimpan dan mengarahkan pengguna langsung ke halaman tahapan terakhir yang belum diselesaikan.
  - **Mulai isi dari awal:** Menghapus seluruh data *draft* lokal yang tersimpan dan mengarahkan pengguna untuk memulai pengisian dari formulir tahap pertama.

## 2. Troubleshooting Bug Registrasi NIK Baru

Saat proses pengembangan dan pengujian alur registrasi, ditemukan kendala di mana pengguna baru tidak dapat melanjutkan proses registrasi ke formulir KYC setelah memasukkan kode OTP.

Aplikasi menampilkan dialog peringatan:

![Warning Registration Data Not Found](/images/september-2026/2026-09-12/01.png)

### Analisis Masalah:
- Pengecekan data registrasi pengguna ditangani oleh **TR 000134**.
- Ketika pengguna mendaftar dengan NIK baru yang belum tercatat di database, TR 000134 mengembalikan kode status `"0"` (status tidak sukses) dengan pesan `"registration data not found"`. Secara logika bisnis bursa/backend, data memang belum ada karena pengguna baru mendaftar.
- Namun, pada `signup_cubit.dart`, seluruh respons TR dengan status `"0"` dianggap sebagai error fatal. Akibatnya, aplikasi memunculkan *warning dialog* dan menghentikan alur pendaftaran, alih-alih mengarahkan pengguna ke formulir registrasi baru.

### Solusi dan Penanganan:
- **Koordinasi Backend:** Masalah penyeragaman status kode pada TR 000134 telah dikoordinasikan ke Mas Philliph untuk penyesuaian di sisi server.
- **Penyesuaian di Sisi Flutter (`signup_cubit.dart`):**  
  Agar proses pengembangan dan pengujian tetap dapat berjalan tanpa terhambat, logika penanganan respons pada `signup_cubit.dart` dimodifikasi:
  - Ditambahkan pengecekan isi pesan respons. Jika TR mengembalikan status `"0"` dengan pesan `"registration data not found"`, aplikasi tidak menganggapnya sebagai error.
  - Aplikasi memperlakukan kondisi tersebut sebagai alur normal untuk pendaftar baru, sehingga proses registrasi tetap dilanjutkan ke formulir pembukaan rekening.
