## Hal yang Dipelajari

### 1. Alur Pemanggilan Order Book pada Flutter (TR 100001)

Pada aplikasi mobile Flutter, tampilan antrean Order Book diperoleh melalui protokol TR:

- **Pengiriman Request:** Aplikasi mengirimkan paket socket TCP dengan nomor TR `100001` beserta parameter kode saham dan papan perdagangan (`RG` / Pasar Reguler).
- **Pemetaan Data (Skema XML):** Respons dari server dipetakan berdasarkan file skema `100001.xml`. Skema ini mendefinisikan 10 tingkatan antrean beli (`bid1` s/d `bid10`) beserta volumenya (`bid1_vol`), serta 10 tingkatan penawaran jual (`off1` s/d `off10`) beserta volumenya (`off1_vol`).
- **Mekanisme Pembaruan Data:** Protokol komunikasi mendukung fungsi siaran (*real-time push/streaming* `RT_Q10`). Namun, pada implementasi saat ini pembaruan data dilakukan melalui mekanisme permintaan berkala (*polling*) secara berkala saat halaman aktif.

### 2. Pengambilan Data di TR Backend (SQL Database)

Server TR memproses permintaan klien melalui skrip Python yang terhubung ke database backend menggunakan koneksi ODBC (`pyodbc`). Skrip menjalankan kueri SQL untuk mengambil *snapshot* data pasar terbaru, lalu merangkai hasilnya ke dalam teks berformat *pipe-delimited*:

```python
def doTr(argv, dbcon):
    stock_code = argv[1]
    board_code = argv[2]

    # Kueri data ringkasan harga dan pasar dari database
    sql = """
        SELECT A.stock_code, cprice, change, change_rate, volume,
               bid_prc, offer_prc, avg_price, ulimit, llimit
        FROM TB_STOCK_MASTER A
        WHERE A.stock_code = ? AND A.board_code = ?
    """
    cur = dbcon.cursor()
    rows = cur.execute(sql, (stock_code, board_code)).fetchall()
    cur.close()

    # Susun hasil kueri menjadi string pipe-delimited
    tr_out = f"{len(rows)}|"
    for row in rows:
        tr_out += (
            f"{row.stock_code}|{row.cprice}|{row.change}|"
            f"{row.bid_prc}|{row.offer_prc}|{row.ulimit}|{row.llimit}|"
        )
    return tr_out
```

### 3. Pemrosesan Data Feed Bursa (Protokol ITCH & Redis)

Untuk memperbarui data antrean pasar secara berkala, server menerima aliran data mentah dari Bursa Efek Indonesia (IDX):

- **Protokol NASDAQ/JATS ITCH (Market Data Feed Level 3):**  
  Bursa mengirimkan data transaksi dan antrean per perubahan (*tick-by-tick*). Pesan-pesan utama yang diproses server antara lain:
  - **`ITCH_A` (Add Order):** Pesan saat ada investor yang memasukkan antrean order baru di pasar.
  - **`ITCH_D` (Delete Order):** Pesan saat suatu antrean order dibatalkan atau ditarik dari bursa.
  - **`ITCH_R` (Order Book Directory):** Informasi referensi data master saham yang dikirimkan bursa pada awal jam perdagangan.
- **Pemanfaatan Redis sebagai Buffer In-Memory:**  
  Sebelum diagregasikan ke tabel database, daemon penerima feed bursa memanfaatkan Redis sebagai penyimpanan berkecepatan tinggi:
  - Database antrean aktif (`db13`) menampung ratusan ribu *keys* tiket transaksi bursa yang sedang berjalan secara *real-time*.
  - Database lain digunakan untuk kebutuhan data agregasi, seperti *caching* riwayat grafik harian (OHLC Candlestick).
